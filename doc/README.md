## Overview

Anthive provides tools to:
1. **Check** h5ad files for consistency and generate metadata
2. **Convert** h5ad files to optimized DuckDB databases
3. **Serve** data through a REST API (future)
4. **Access** data with a lightweight client (future)

## Getting Started

### Basic Workflow

```bash
# 1. Check an h5ad file (validates and creates metadata)
ant check mydata.h5ad

# 2. Review and edit mydata.md if needed
# (adjust include/exclude lists, add description)

# 3. Convert to DuckDB
ant convert mydata.h5ad

# Result: mydata.duckdb ready for querying
```

### Directory Structure

```
project/
├── anthive.yaml          # Optional configuration
├── dataset1.h5ad         # Input: single-cell data
├── dataset1.md           # Metadata (generated by ant check)
├── dataset1.duckdb       # Output: optimized database
├── dataset2.h5ad
├── dataset2.md
├── dataset2.duckdb
└── index.md              # Collection metadata
```

## Design Principles

### 1. Fail Fast
Better to crash with a clear error than leave corrupt data.
See [ERROR_HANDLING.md](ERROR_HANDLING.md).

### 2. Human-Readable Metadata
YAML preambles in markdown files allow both machine processing and human editing.
See [METADATA.md](METADATA.md).

### 3. Space Efficiency
Integer indices, sparse storage, and ENUM types minimize disk usage.
See [DATABASE_SCHEMA.md](DATABASE_SCHEMA.md).

### 4. Memory Awareness
Chunk-based processing handles datasets larger than available RAM.
See [PERFORMANCE.md](PERFORMANCE.md).

### 5. Preserve Original Data
Never modify source h5ad files. Store original cell/gene names.
See [CONVERT_PROCESS.md](CONVERT_PROCESS.md).

## File Naming Conventions

- `anthive.yaml` - Configuration file
- `anthive.default.yaml` - Default configuration reference
- `<basename>.h5ad` - Input h5ad file
- `<basename>.md` - Per-file metadata
- `<basename>.duckdb` - Output database
- `index.md` - Per-directory collection metadata

## Key Concepts

### Mutually Exclusive Lists
Each obs/var column appears in exactly ONE of:
- `obsnum_include` / `varnum_include` (numerical)
- `obscat_include` / `varcat_include` (categorical)
- `obs_exclude` / `var_exclude` (excluded)

See [METADATA.md](METADATA.md) for details.

### Sparse Storage
Expression layers store only non-zero values with integer cell/gene IDs.
Typical compression: 70-90% space savings.

See [DATABASE_SCHEMA.md](DATABASE_SCHEMA.md) for details.

### Chunk Processing
Large datasets processed in chunks to avoid out-of-memory errors.
Configurable via `melt_chunk_size`.

See [PERFORMANCE.md](PERFORMANCE.md) for tuning guidance.

### Schema Versioning
Database includes `__schema_version` table for future migrations.
Current version: 1.

See [DATABASE_SCHEMA.md](DATABASE_SCHEMA.md) for schema details.

## Common Tasks

### Adjusting Memory Usage

Edit `anthive.yaml`:
```yaml
melt_chunk_size: 5000  # Reduce for less memory usage
```

See [CONFIG.md](CONFIG.md) and [PERFORMANCE.md](PERFORMANCE.md).

### Excluding Problematic Columns

Edit `<basename>.md` preamble:
```yaml
obs_exclude:
  - problematic_column
  - another_bad_column
```

Re-run `ant convert`.

### Checking File Changes

```bash
ant check mydata.h5ad
```

If h5ad changed since last check, checksum mismatch will be reported.

See [CHECK_PROCESS.md](CHECK_PROCESS.md).

### Handling Out-of-Memory Errors

1. Reduce `melt_chunk_size` in `anthive.yaml`
2. Close other applications to free RAM
3. Consider running on a larger machine
4. For extremely large datasets, use high-memory compute nodes

See [PERFORMANCE.md](PERFORMANCE.md) for guidance.
