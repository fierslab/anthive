Anthive help

Anthive is a browser for curated single-cell RNA-seq data, mostly human microglia and other brain cells in health and Alzheimer's disease, together with a library of the papers behind it. {% if n_datasets is not none %}It currently holds {{ n_datasets }} datasets{% if n_collections is not none %} in {{ n_collections }} collections{% endif %}{% if n_genesets is not none %} and {{ n_genesets }} gene sets{% endif %}.{% endif %} You can explore it in the browser, from your own code, or through an AI assistant connected with your personal MCP link.

Quick start
  1. Sign in and look around. The site asks for your login once per session. The front page lists every collection; type in the search box (a gene, a disease, an author, a dataset code) or open Filters, then open a dataset to see its cells, plots and papers.
  2. Connect your AI client. MCP is the way AI assistants use outside tools; a personal MCP link lets yours use anthive as you. Open your name at the top right and choose Connect an MCP client, which takes you to your MCP page, and create a link there. Keep it private, it works like a password.
    • Agents that can run commands (Claude Code, Codex, OpenCode, Cursor) are quickest. Copy the setup prompt from your MCP page and paste it into the agent: it connects anthive and installs the skills in one go, so you can skip step 3.
    • Other clients, including Claude Desktop and claude.ai, are set up by hand. Your MCP page has ready-made snippets with your link filled in, and the client guide on GitLab walks through more than 20 clients step by step.
  3. Install the skills. Skills are short written instructions your assistant reads when a task fits: which tool to use first, how to cite, which statistics not to trust.
    • In Claude Code, Codex, OpenCode, Cursor, Gemini CLI and most other agents that read skill folders, run this once in a terminal. It needs Node.js, the free program that provides npx.

  4. Ask a first question. For example:

What anthive is
  • Datasets are single-cell (or bulk or spatial) expression matrices with their cell annotations, converted from curated .h5ad files into fast databases. Each has an id such as L26/FMG: the collection code, then the dataset code. A small grey version such as v0.1.4 marks the dataset release: a minor bump means the data changed, a patch bump means only the metadata did.
  • Collections group the datasets that come from one study or source, usually one paper.
  • Papers live in the paper library: the publications behind the datasets plus papers kept for background, with their full text searchable.
  • Gene sets and module scores: curated gene modules, scored per cell in many datasets.
  • Facets: standardised annotation columns (ant_*) that mean the same thing in every dataset, so you can compare across studies.

The site is maintained by the BADS lab at KU Leuven (Mark Fiers). The software and its documentation are on GitLab.

Finding data

The front page lists every collection, newest first.

  • Search box. Type anything: a paper title, an author, a journal or year, a DOI or PubMed id, a tissue, cell type, disease or method, a collection or dataset code, or the name of a dataset inside a collection. Several words must all match (so microglia prefrontal narrows the list). Case and accents do not matter, and matching words are highlighted.
  • Shortcut and sharing. Press / anywhere on the page to jump to the search box. The search is kept in the address bar, so you can copy the URL to share exactly the list you see.
  • Filters. The Filters button opens chips for organism, cell type, tissue, method and disease, with counts. Chips in one group combine as OR, chips in different groups as AND. Filters are also kept in the URL and remembered in your browser.
  • Tags only where it matters. Each collection shows small tags only for what is unusual in this catalogue (for example mouse, spatial, astrocytes, prefrontal cortex). The common case (human, brain, microglia, single-cell RNA, Alzheimer's) is not repeated on every row. Collections whose access differs from the usual get a small mark (for example public).
  • Sorting. Recently added, paper year, number of cells, or name.
  • Table view. The Table view button switches to a classic table with all columns, following the same search and filters.

Collection and dataset pages

Collection page

Lists the datasets of one collection with their size and the annotations that differ between them (values shared by all datasets are shown once, as pills under the title). Below the table: the collection description, the linked papers (with why they are linked) and downloads.

Dataset page

At the top: the id strip with the collection, dataset and database ids (click to select and copy; you need the database id, for example L26/FMG, in the API, vark, pyvark and MCP), provenance (access, source, license, links to the DOI or accession), the title, a short description, context pills and the numbers of cells and genes. The visualize menu (top right) opens the plot builder.

Facets (ant_* columns)

Columns starting with ant_, such as ant_cell_type, ant_disease, ant_donor, ant_sex, ant_age, ant_braak and ant_apoe, are the site's standardised annotations: same name and same values in every dataset that has them. Prefer them when you group, colour or filter, and when you compare datasets. They are shown in bold with a small facet pill; the tooltip gives the original column name.

The facet ant_apoe4_carrier (APOE e4 carrier) was called ant_apoe_carrier until October 2026. The old name still works in URLs, API calls and the facet tests for one release; please switch to the new one.

Plots
  • Where. Use the visualize menu on a dataset page, or the small chart icons next to a column. Plots are rendered on the server, so they work on very large datasets.
  • Plot types. Scatter and hexbin (on an embedding such as UMAP, or one variable against another), violin, box, bar, histogram, ECDF, KDE and 2-D KDE, heatmap, rolling average along a variable, and for differential expression: volcano, MA, forest and DE heatmap.
  • Colour, subset and sample. Colour by a gene or a column; restrict to a subset of cells (for example one sex or one disease group); subsample very large datasets for speed. Settings such as palette and size live in the side panel.
  • Downloads. PNG, SVG or PDF. Figures contain no visible caption text, so they are clean for manuscripts; the caption is available separately.
  • Sharing. copy URL copies the address of the interactive plot page with all settings; copy thumbnail md copies a snippet to embed the plot in a description.
  • Notebook. 📓 notebook opens the same plot as a JupyterLite notebook in your browser, with the code to fetch the data and redraw it. Download the notebook to keep changes.

Genes, gene sets and facets
  • Gene atlas. Open genes in the top bar and type a gene to see it across all datasets; several genes separated by commas give a heatmap. Favourite genes (set in Preferences) are marked.
  • Reading the dots. In the gene tables (dataset Genes tab, gene atlas) and the gene set variability tables, each value is also drawn as a big dot on a thin grey line. The position is the value on that statistic's range, from the left end (lowest) to the right end (highest); the colour shows the low (red), middle (amber) or high (green) third. Hover a dot for the exact value. Green always means the higher, more notable end, and the position carries the same information for readers who cannot tell the colours apart.
  • Gene sets (/genesets): browse curated gene sets by study and experiment, open one to see its genes and where its module score varies most, or look up every set containing a gene. The variability heatmap compares modules across datasets; its numbers are per-cell associations (descriptive), computed over cells and not over donors (see Per cell vs per donor).
  • Module scores are computed per cell with scanpy (default) or UCell; choose the method in Preferences.
  • Facets browser (/facets, marked EXP): every facet with how many datasets carry it, its definition and its donor-level effects across datasets. Each dataset has a Facets tab with the same information for that dataset. It is experimental: numbers and groupings may still change.

Per cell vs per donor

Two kinds of numbers on the site look alike and mean different things.

  • Facet effects are per donor. On the Facets tab of a dataset, an effect is tested within one cell type, with the donor (or host animal) as the unit of replication. A donor's cells are added up into one profile first, so ten thousand cells from one donor count once. These are the numbers to quote, as exploratory results.
  • A per-cell association (descriptive) is not a test. The omega², spearman and similar values in the Genesets tab, on the gene set pages and in the variability heatmap are computed over individual cells. Cells of one donor are not independent, and every cell carries its donor's facet value, so these numbers mostly measure how different donors are from each other. They help to find candidates and show where a score differs, not whether a difference is real. Columns such as donor or cluster are off in the default view because they explain a lot by construction. The same applies to the spread across cells column on the Genes tab, the standard deviation of the log-normalised expression across cells.
  • Mouse and xenograft datasets. The replicate there is the host animal, not the human donor of the transplanted cells. Facet tests exist for them too (the App NL-G-F facet in particular), and they are never combined with human post-mortem data.

Facet effects are explained in Facets and facet effects, and every term is defined in the glossary.

Facets and facet effects

A facet is a donor-level (or animal-level) variable that anthive has standardised across datasets: the same name and the same values in every dataset that has it. Each dataset declares how its own columns map onto a facet, and the Facets tab of a dataset shows that mapping value by value. A facet is constant for all cells of one donor, so a facet effect is a difference between donors, not between cells.

The facets that are tested are sex, pathologic AD (disease), APOE e4 carrier status, Braak stage, age (per decade of age, both unadjusted and adjusted for pathology) and, in mouse and xenograft hosts, App NL-G-F genotype. The tissue facet uses umbrella terms (for example cortex) so that datasets with different dissections can be compared. Only the tested facets are shown on the facet pages while the audit of the facet definitions is open; the Facets tab of a dataset still lists every facet it has, the others under "Not analysed yet". The other ant_ columns stay in the data, the plots, SQL and the API.

What was tested

For each dataset and each cell type in it, the facets are tested at the level of the replicate: the donor for human cohorts, the host animal for mouse and xenograft data. The raw counts of a replicate's cells in that cell type are added up into one pseudobulk; replicates with fewer than 10 such cells are left out. Genes are tested with limma-voom with sample quality weights and robust moderation, adjusting for sex, age and post-mortem interval when these are known for enough donors, and for a batch column when one exists and is not confounded with the facet. Each row says which covariates were included; a row without age adjustment can carry age-related genes into a disease or Braak result.

q values are Benjamini-Hochberg adjusted within one dataset, cell type and facet (FDR). A second test, limma treat, asks whether the change exceeds a 10 percent minimum; its q is shown next to the ordinary q. Module (gene set) scores are summarised per donor and tested with an ordinary linear model plus permutations of the facet labels across donors (10,000 by default; the model line of each row gives the number used).

Every result row states its exact model. Click details next to the model line for the cell type definition, the formula (for example expression ~ braak + sex + age_z + pmi_z), which covariates were left out and why, the donors per group, the multiple-testing scope, and the tool version, seed and run date. Anything the run did not record says "not recorded".

Replicate unit and analysis level

Each dataset declares what an independent replicate is: a donor for human cohorts, the host animal for xenografts and mouse data (the human donor line of a xenograft is never the replicate), a sample for some bulk and in vitro data, or none. The Facets tab shows it as Replicate unit (for example "donor (ant_donor)"), and the Data tab repeats it.

A unit is tested at replicate level when the dataset has a replicate unit and at least 3 replicates in every group of a two-group facet (at least 4 replicates over at least three distinct values for a trend such as Braak or age). Otherwise it is cell-level, descriptive only: no test, p or q is given, because cells are not replicates and treating them as such would make a difference between two donors look highly significant. The reason is stated on the unit (analysis level).

How many replicates are needed

A unit is fitted from 3 replicates per group (4 replicates over at least three distinct values for a trend). p and q values are given from the p-value floor: 5 donors per group (10 donors for a Braak or age trend) in human cohorts, and 3 animals per group (6 for a trend) in xenograft hosts, where animals of one line and age vary far less than human donors. Between the fit minimum and the floor the row reads "descriptive: below the p-value floor (donors need 5 per group)": an estimate without p, q or interval, not counted towards replication. A unit above the floor but with fewer than 5 replicates per group is flagged small sample: tested and counted, with little power. With 5 donors per group only large effects can be detected; a missing hit means "not detected with this many donors", not "no effect".

Scopes: human post-mortem and xenograft

Every facet result belongs to one scope. Human post-mortem covers cells from human brain tissue (post-mortem or biopsy), where the replicate is the donor. Human cells in mouse hosts (xenograft) covers human cells grafted into mouse brain, where the replicate is the host animal and the gene is the human gene in a mouse environment. The scopes are tested, counted and replicated separately and never mixed. Facet pages have a scope selector, the gene page has one above its facet tabs, and every result block carries its scope label. In vitro cultures are listed but not tested; pure mouse datasets are not part of the facet analysis at all.

Datasets left out of the facet analysis

The analysis needs single cells or nuclei that can be grouped by cell type and donor. Spatial data (a spot is not a cell), proteomics, metacell sets (each row an aggregate of cells), pure mouse datasets and a few sets set aside by the curators (for example the Francken2026 sets, for now) are therefore left out: they keep their facet columns for browsing and plotting, but have no tests and no replication. Their dataset page says why in plain words on the Facets tab (glossary).

Contrasts and other row details

  • Contrasts. Sex is m vs f, disease is pathologic AD vs control, APOE e4 carrier vs non-carrier, App NL-G-F vs control. A positive log2 fold change means higher in the first-named group. Braak stage and age are numbers, so their effect is the change per Braak stage and per decade of age.
  • Composition. This flag means the fraction of each donor's cells in the cell type changes with the facet (p < 0.05, uncorrected). It tests only the size of the cell type, not the mix of states inside it (see composition).
  • Batch. "batch adjusted" means a batch column entered the model; "batch confounded" means the facet cannot be separated from batch and batch was left out.
  • Inflation. A unit whose lambda is above about 1.3 is flagged: many genes shift together, which usually points to a batch, chemistry or composition difference rather than to biology.
  • Provisional. Disease results depend on vocabulary decisions that are still open (what counts as control differs between studies), so they may change.
  • Permutation q. A permutation p cannot go below 1/(n + 1) for n permutations (about 0.0001 with 10,000). After Benjamini-Hochberg over m modules, one strong module reaches at best q_perm of about m/(n + 1), which is below 0.05 only when fewer than about 500 modules were tested. Read q_param and p_perm together.
  • Per-cell numbers. The variability heatmap and the per-cell association columns are labelled per-cell (descriptive). They carry no test; for effects per replicate use the Facets tab.

Replication across cohorts and how to read it

Replication across cohorts

A gene is called replicated for one facet and cell type group when its r-value is below 0.05. The r-value comes from a partial conjunction test of "changes in the same direction in at least 2 of the m cohorts" (Benjamini and Heller 2008): the smallest cohort p value is set aside, the remaining ones are combined by Simes' method, the result is doubled for the two directions and adjusted over all genes of the group. Each cohort contributes one anchor unit, so datasets that share donors cannot count twice. Replication is only counted within one scope: human post-mortem and xenograft results are never combined.

r below 0.05 means that among all genes listed as replicated about 5 percent are expected to be false entries. It is a statement about the list, not a probability for one gene, and it does not say how large the effect is. The badge names the two cohorts that carry the result. m counts every cohort that tested the gene, including small ones that could not detect the effect, and the badge says how many of them have fewer than 20 donors.

Effect size: the 10 percent filter and the second tier

Separately from the r-value, a gene is marked "at least 10 percent in 2 cohorts" when at least two counted cohorts show a log2 fold change of at least 0.14 in the replicated direction (for Braak 0.046 per stage, a 10 percent change over three stages; for age 10 percent per decade). This effect filter acts on the estimates and is not part of the error control, so the list of genes that pass both conditions can contain somewhat more than 5 percent false entries. A second, stricter tier, "replicated with at least 10 percent change", repeats the partial conjunction on the treat p values (treat tier). The cohort estimates and confidence intervals are in the forest.

Reading "no evidence of replication"

"No evidence of replication" means the data at these donor numbers do not support a shared effect. It does not show that the effect is absent. "Tested in one cohort only" means replication could not be assessed. Cohorts with 9 controls (SEA-AD for pathologic AD) or 17 donors (Fancy2024) rarely contribute. k of m counts the cohorts that individually reach q below 0.05 in the replicated direction; it depends strongly on donor numbers (a 1,000-donor cohort almost always counts, a 17-donor cohort almost never does) and is descriptive.

Cell type groups and what counts

Datasets name their cell types differently ("microglial cell", "Microglia", "MG", "Mic P2RY12"). For counting, every label is placed in a cell type group (microglia, astrocyte, inhibitory neuron, and so on) from the table lib/celltype_groups.yaml; the raw label stays visible in small text next to the group. Mixed populations (myeloid, glia, immune, vascular) have their own groups and never count as evidence for a pure class, and labels without a group are "unmapped" and never count. Neuron groups are coarse and can combine brain regions, so read the raw labels before drawing a biological conclusion.

  • One anchor per cohort and cell type group. Each cohort contributes exactly one unit to a group, however many of its datasets were tested: a donor-pooled unit (pool:<id>, marked "pooled") for multi-region cohorts such as MADRC and SEA-AD, otherwise the dataset named as anchor in the DRAFT cohort selection table. Other units of the cohort stay on the card, folded, each with the reason it is not counted.
  • What does not count. Descriptive-only and cell-level rows, reanalyses (datasets that re-serve cells of another dataset, marked "reanalysis, not counted"), cohorts whose role is a duplicate, supplement or alternative, datasets missing from the cohort table and unmapped labels. For disease, cohorts with a clinical or author diagnosis do not count either.
  • One source per dataset. Within a dataset and group only the rows with the most direct cell type source count: per-cell ant_cell_type or a dataset constant first, then author cell type columns, then author clusters.
  • Several strata in one group. When several equal strata of the anchor dataset fall into the same group, they share the cohort's single vote and their p values are multiplied by the number of strata (Bonferroni); the forest shows this as "×n" under q.
  • Why Simes. Cohorts are not independent (shared pathology and cell-state shifts, sometimes shared persons). Fisher's method assumes independence and calls more genes replicated than the data justify.
  • Donor overlap. Cohorts whose donor independence was never checked are still counted but flagged "donor overlap not checked", because shared donors make agreement look stronger than it is.

Replicated genes on a facet page are ranked by (1) the r-value, smallest first; (2) k; (3) agreement; (4) the median absolute log2 fold change over the tested cohorts. Which datasets are primary data and which are reanalyses is listed on the donor groups page and shown at the top of each dataset page.

Pathologic AD and Braak are one axis

In every pathology-based cohort, "AD" is defined from Braak stage and CERAD plaque score (AD is Braak III or higher with moderate or frequent plaques; control is Braak II or lower with no or sparse plaques; other donors are left out). A gene replicated under both Braak and pathologic AD is one observation read twice, not two findings. Some pathologic AD donors had no dementia, so this is not a clinical diagnosis (disease basis).

Age: two twins

The age facet is a straight-line trend per decade of age at death, in donors of 60 years and older (younger donors are left out; a dataset can declare another floor). Age and AD pathology are correlated in every brain bank, so the age result is tested twice. Age, not adjusted for pathology re-detects part of the pathology signal. Age, adjusted for pathology adds Braak stage (else pathologic AD) to the model; what remains is age beyond pathology. A gene row of the unadjusted test says whether the association persists after pathology adjustment. In ROSMAP ages above 90 are recorded as 90, which flattens the oldest donors (glossary).

Sensitivity analyses

Two extra tests check whether a Braak or APOE result depends on how the facet was coded. Braak stage III or higher against II or lower replaces the straight-line trend by a two-group contrast; APOE e4 dose (0, 1 or 2 alleles) replaces carrier against non-carrier by a trend per allele. They are shown as tabs next to their parent facet, are counted separately, and are one observation read twice with it, not independent findings.

App NL-G-F

In xenograft datasets the facet contrasts App NL-G-F knock-in host mice with control hosts. The host animal is the replicate. The control is stated on every unit (control basis): the humanised-App host (App hu/hu) isolates the three familial AD mutations, a wild-type host does not. Units are formed per grafted human line and per timepoint where these vary, because the amyloid response grows with age and differs between lines; a unit where genotype cannot be separated from line or timepoint is not tested. These tests detect large effects only (a handful of animals per genotype), and the cells were isolated live, which can itself induce dissociation-response genes (FOS, JUN, heat-shock genes, NFKBIA). Human microglia in mouse hosts and human post-mortem microglia are never combined. The genotype of the grafted cells is a different facet (genotype and host genotype).

Tissue, genotype and author clusters

  • Tissue is a coarse umbrella term (prefrontal cortex, temporal cortex, hippocampus, white matter and so on) so that datasets with different dissections can be compared. The most specific term of a dataset stays in the plain column tissue_uberon, which is shown as detail on the dataset's Facets tab and is not a facet (glossary).
  • Genotype and host genotype. ant_genotype is the genotype of the sequenced cells (the grafted line, or the donor); ant_host_genotype is the genotype of the mouse host. The tested App NL-G-F facet is derived from the host genotype.
  • Author clusters are published per cell type (ant_mg_author_cluster for microglia, and the same for astrocytes, oligodendrocytes, OPCs, excitatory and inhibitory neurons and endothelial cells). They are dataset-scoped: a label such as L26/FMG/cluster_Homeo only has meaning inside one cell type of one dataset, so these facets are shown as a mapping table only, with no gene tests and no comparison across datasets (glossary).

What a whole-cell-type effect can mean

A pseudobulk within a cell type does not separate a change inside cells from a change in the mix of states within the cell type. In AD microglia the dominant published effect is a shift toward lipid-associated and MHC-II-high states, so a rise in GPNMB, APOE, SPP1 or PTPRG at the whole-microglia level is at least partly "more cells in that state". Both are real donor-level effects; neither on its own shows that a gene is induced within a cell.

Technical genes

Mitochondrial transcripts, ribosomal proteins, long intron-rich genes and lncRNAs track nuclear RNA quality, post-mortem interval and ambient RNA in nuclei data, and are flagged on the gene row. A microglial gene changing in an astrocyte unit (for example INPP5D) is most likely ambient RNA or doublets, and the unit shows a foreign-marker flag when such genes move with the facet. Cytoplasmic transcripts such as cytokines are under-represented in nuclei, so a null for them is not informative.

Limits

All of this is exploratory. No hit means "not detected with this many donors", not "no effect". The same donors occur in several datasets (ROSMAP, SEA-AD, MADRC and others), which is why each cohort counts once through its anchor and why overlap that was never checked is flagged. Replication is a statement about which genes change in at least 2 cohorts; there is no pooled effect size across datasets.

The full method, thresholds and outputs are described in DESIGN_facet_testing.md; the code is bin/annot/ant-facet-test and bin/annot/ant-facet-test-modules in the anthive4 repository. The results are also available through the API (/api/databases/{id}/facet-tests, /api/facets/{name}/tests) and the MCP tool get_facet_tests.

How to read a facet result: PTPRG in microglia with Braak stage

A worked example of the logic. The numbers are from one saved run and shown per dataset; the live card pools some cohorts, so its exact values differ.

  1. Open the gene page for PTPRG and the Braak tab. The facet is a trend: the effect is the log2 fold change per Braak stage in microglia pseudobulks, adjusted for sex, and for age and post-mortem interval where the cohort had at least 15 donors with those values.
  2. Look at the anchors table first. One row per cohort. ROSMAP: 413 donors, +0.58 per stage, q 1.1e-16 after the correction for three sibling strata. SEA-AD: 84 donors, +0.48 per stage, q 0.0013. MADRC: about 30 donors, +0.33 to +0.55 in five regions, pooled into one estimate. Lee2026 (PsychAD without its ROSMAP participants): 1,122 donors, +0.43 per stage, q 3e-85. Fancy2024: 17 donors, +0.53 per stage, q 0.12. All five estimates have the same sign; the confidence intervals of the three small cohorts are wide.
  3. See how the r-value arises. The smallest p value (Lee2026) is set aside, because it must not carry the result alone. The remaining four are combined by Simes: the smallest of them (ROSMAP) is multiplied by 4 for the four values, then by 2 for the two directions. Benjamini-Hochberg over the roughly 15,000 microglia genes tested in at least two cohorts leaves r far below 0.05, so the badge reads "replicated (up)" and names ROSMAP and Lee2026 as the two cohorts that carry it. Without ROSMAP the second-best p value would have been SEA-AD's (about 1e-4), and the gene would most likely not have passed. That is what the badge should make visible: this replication rests on two large cohorts plus consistent direction in three small ones.
  4. Read k of m and agreement. k is 3 or 4 of 5 depending on the MADRC pool; agreement is 5 of 5. Fancy2024 is in m although it could not reach significance; it only dilutes the r-value slightly and adds a consistent sign.
  5. Check the effect filter. The per-stage threshold is 0.046 and every cohort is far above it; the median over the anchors is about +0.48 per stage. Over six stages that is a log2 change near 2.9, a seven-fold difference between Braak 0 and VI, which is large for a pseudobulk.
  6. Ask what it means biologically before quoting it. Green et al. 2024 (Nature 633:634) name the lipid-associated, tau-coupled ROSMAP microglial subpopulation "Mic.13 (PTPRG)", and Wachter et al. 2024 (Acta Neuropathol 147:65, the MADRC dataset here, so not independent) list PTPRG among the top regulated genes of pathology-associated clusters. The published effect is a change in the proportion of a state. A seven-fold whole-microglia change is therefore mostly "more Mic.13-like nuclei at high Braak", not "every microglial cell makes seven times more PTPRG". The composition flag tests the size of the microglia fraction, not this. PTPRG is also a 730 kb gene, and long intron-rich genes track nuclear RNA integrity and post-mortem interval, so check that units with and without that adjustment agree. Finally, the disease tab shows PTPRG up with pathologic AD in the same cohorts; that is the same axis, not a second finding.
  7. What you may say. "PTPRG expression in microglia pseudobulks rises with Braak stage in ROSMAP and PsychAD, with the same direction in SEA-AD, MADRC and Fancy2024 (partial conjunction r below 0.05, median about 0.48 log2 per stage), consistent with the expansion of the PTPRG-marked lipid-associated state reported by Green et al. 2024." What you may not say: "PTPRG is induced in microglia by tau pathology", "replicated in five independent cohorts", or anything about causation.

Glossary

Short definitions of the terms used on the facet, gene and gene set pages. The info balloons on those pages link here.

Facet
A donor-level or animal-level variable that anthive has standardised across datasets, such as sex, pathologic AD, Braak stage, APOE e4 carrier status, age or App NL-G-F genotype. Every dataset declares how its own column maps onto the facet. A facet is constant for all cells of one donor, so a facet effect is a difference between donors, not between cells.
Replicate unit
The thing that counts as one independent observation in a test: the donor for human cohorts, the host animal for mouse and xenograft studies, the sample for some in vitro data. Cells are never replicates, because thousands of cells from one donor tell you about that donor, not about donors in general.
Pseudobulk
All cells of one replicate within one cell type are added up into a single expression profile, as if that donor's microglia had been sequenced in bulk. The test then compares these per-donor profiles. Summing removes cell-to-cell noise and makes the donor the unit of the test.
Analysis level
Whether a unit was tested on one profile per replicate ("replicate level") or can only be described per cell ("cell-level, descriptive only"). Replicate level needs a replicate column and at least 3 replicates in every group.
Descriptive only
A unit that cannot be tested: no replicate column, or fewer than 3 replicates in a group. The numbers describe cells, and no p or q value is given, because treating cells as replicates would make a difference between two donors look highly significant. A unit that was fitted but has fewer replicates than the p-value floor is labelled "descriptive: below the p-value floor" instead.
limma-voom
A standard method for testing expression differences in count data with few samples. "voom" converts counts to a log scale and estimates how precise each measurement is; limma then fits a linear model per gene with the facet and covariates. It is the usual choice for pseudobulk single-cell data.
Moderated test (eBayes)
With a handful of donors, the variance estimated for one gene is unreliable. limma borrows information across all genes to stabilise it, which makes it less likely that a gene looks significant only because its variance happened to be estimated too low. With "robust" moderation, genes with unusually high or low variance are not shrunk too far.
Covariates (sex, age, PMI, batch)
Other donor-level variables included in the model so that their effect is not mistaken for the facet effect. They enter only when known for enough donors, and each unit says which were included or left out. A unit without age adjustment can carry age-related genes into a disease or Braak result.
log2 fold change
The size of an effect on a log scale with base 2. A value of 1 means two-fold, 0.14 means about 10 percent, and the sign gives the direction (positive is higher in the first-named group, or increasing per Braak stage or per decade).
FDR and q value
The p value is the probability of seeing an effect at least this large if there were none. The q value is the Benjamini-Hochberg adjustment for the thousands of genes tested in one unit: if you take all genes with q below 0.05, about 5 percent of them are expected to be false. A q value is a property of the list, not a probability for the gene.
treat (minimum-effect test)
A variant of the limma test that asks whether the change is larger than a chosen minimum, here a 10 percent change, instead of larger than zero. A gene with a tiny but very precisely measured change has a small ordinary p value and a large treat p value.
Cohort
A set of donors from one brain bank or study. Several datasets can come from one cohort (ROSMAP has four datasets here; SEA-AD has one file per cell class and region), and they share persons, so a cohort counts once in replication. A reanalysis of cells another dataset serves is shown but never counted.
Anchor unit
The single dataset and cell type unit that represents a cohort in the replication count for one cell type group. For multi-region cohorts it is a pooled unit (one pseudobulk per donor over the regions). All other units of that cohort are shown but do not count.
Pooled unit
A per-donor pseudobulk made by adding a donor's cells over several files of the same cohort (for example SEA-AD MTG plus PFC). It gives the cohort one vote and ignores region differences.
Cell type group
Datasets label cell types differently. Each label is placed in a group (microglia, astrocyte, ...) so that replication is counted within comparable cells. Mixed groups (myeloid, glia, immune) never count as evidence for a pure cell type.
Scope
The kind of system a dataset comes from: human post-mortem (cells from human brain tissue; the replicate is the donor) or human cells in mouse hosts, a xenograft (the replicate is the host animal). Facets are tested, counted and replicated within one scope, so a xenograft result never supports a human post-mortem one, and genes are never merged across scopes. In vitro cultures are listed but not tested; pure mouse datasets are outside the facet analysis.
Partial conjunction test
A test of the statement "this gene changes in the same direction in at least 2 of the m cohorts". It is built so that one very large cohort cannot carry the result alone: the single smallest p value is set aside and the rest are combined with Simes' method, which is valid for positively correlated cohorts (shared pathology, protocols, sometimes brain banks). Only when the second-best cohort is also convincing does the gene pass.
r-value and "replicated"
The false discovery rate for the statement "replicated in at least 2 cohorts, same direction", adjusted over all genes of one facet and cell type group. Genes with r below 0.05 form a list in which about 5 percent are expected to be false entries. An r-value is not the probability that this particular gene is real, and it says nothing about the size of the effect.
k of m
m is the number of cohorts that tested the gene, including small ones that could not detect the effect; k is how many of them individually reached q below 0.05 in the replicated direction. It is descriptive, and k depends strongly on donor numbers.
Agreement
The fraction of the m cohorts whose estimate has the replicated sign, significant or not. Descriptive.
Effect filter (at least 10 percent in 2 cohorts)
A filter on the estimates: at least two counted cohorts show a change of at least 10 percent (log2 fold change at least 0.14; for Braak 0.046 per stage, which is 10 percent over three stages; for age 10 percent per decade) in the replicated direction. It is shown separately from "replicated" and is not part of the error control, so a list passing both conditions can contain somewhat more than 5 percent false entries.
Treat tier (replicated with at least 10 percent change)
A second, stricter tier: the partial conjunction test repeated on the treat p values, which ask whether the change exceeds 10 percent rather than zero. Genes in this tier are replicated and large enough to matter at an FDR of 5 percent for that statement.
Composition caveat
The flag means that the fraction of a donor's cells that fall in this cell type changes with the facet. Separately, and not flagged, the mix of states within the cell type (for example more lipid-associated microglia in AD) changes the pseudobulk even if no gene changes within any cell. A whole-cell-type effect can be either.
Disease basis and pathologic AD
How AD versus control was defined in a dataset: from Braak and CERAD neuropathology (the common definition here), from the NIA-Reagan or ADNC schemes, or from a clinical or author diagnosis. Only pathology-based definitions are combined. "AD" on these pages means pathologic AD; some such donors had no dementia.
Donor overlap not checked
Nobody has verified whether this cohort shares persons with another counted cohort. Shared persons make cohorts agree for the wrong reason.
Lambda (inflation factor)
The median test statistic of a unit divided by its expected value under no effect. Around 1 means the unit is well calibrated; values above about 1.3 mean many genes shift together, which usually points to a batch, chemistry or composition difference rather than to biology.
p-value floor
The number of replicates a unit needs before it reports p, q and confidence intervals: 5 donors per group (10 for a trend such as Braak or age) in human cohorts, 3 animals per group (6 for a trend) in xenograft hosts. Between the fit minimum (3 per group) and the floor the unit is fitted but shown as "descriptive: below the p-value floor": an estimate without p, q or interval, not counted towards replication.
Small cohorts and "m includes n cohorts below 20 donors"
Every cohort that tested a gene counts in m, however small, so a very small cohort cannot make a result look better than it is but also cannot detect much. The badge says how many of the m cohorts have fewer than 20 donors, because the result then rests on fewer, larger cohorts than m suggests. A unit with fewer than 5 replicates per group is flagged "small sample".
Age: not adjusted and adjusted for pathology
Age is tested twice: once on its own (which partly re-detects AD pathology, since older donors have more of it) and once with Braak stage, else pathologic AD, in the model. A gene "persists after pathology adjustment" when its age association is still present in the adjusted test. Age is per decade, from 60 years; ROSMAP ages above 90 are recorded as 90.
App NL-G-F and control basis
The App NL-G-F knock-in is a mouse model of amyloid pathology. In xenograft studies the host mouse can carry it, and the facet compares those hosts with control hosts. The control basis says what the controls are: the humanised-App host (App hu/hu) carries the human Abeta sequence without the three familial AD mutations, which isolates the mutations; a wild-type host differs in the Abeta sequence as well. The replicate is the animal, strata are formed per grafted line and timepoint, and the test detects large effects only.
Genotype and host genotype
Two different facets in a xenograft: ant_genotype is the genotype of the sequenced human cells (the grafted line, for example APOE e4/e4 or TREM2 R47H); ant_host_genotype is the genotype of the mouse they grew in (for example App NL-G-F). The tested App NL-G-F facet is derived from the host genotype.
Author cluster (per cell type)
The authors' own clusters or states inside one cell type of one dataset, kept as published and written dataset/cluster_label. A cluster label is only comparable inside its dataset and cell type, so these facets are a mapping table only: no gene tests, no comparison across datasets.
Tissue umbrella term
The coarse brain region of a dataset (prefrontal cortex, temporal cortex, hippocampus, white matter, ...) from a fixed table, so that different dissections of the same region fall in one group. The most specific term stays in the plain column tissue_uberon, which is detail and not a facet.
Left out of the facet analysis
Datasets that cannot be analysed by donor and cell type: spatial data, proteomics, metacell sets, pure mouse datasets and sets the curators set aside. They keep their columns for browsing and plotting but have no facet tests and no replication.
Gene class flags (MT, ribosomal, lncRNA / clone, sex chromosome, long gene, APOE locus)
Small labels on a gene for classes that are over-represented among facet hits for technical or locus reasons: mitochondrial genes and ribosomal proteins track cell quality, lncRNAs and clone-named transcripts are poorly annotated, sex-chromosome genes follow sex composition, genes over 500 kb are intron-rich and track nuclear RNA quality and post-mortem interval, and genes near APOE can show allele-linked differences that need not be biology. The flag is a reason to read the result with care, not a verdict.
Sex check
The recorded sex of each donor is checked against XIST and Y-linked expression. "n of m sex labels disagree" means the expression contradicts the label for those donors, so the label or the donor assignment may be wrong.
Per-cell association (descriptive)
Statistics such as omega squared or Spearman computed over cells rather than donors. Because all cells of a donor share the donor's facet value, these numbers mostly measure how different donors are from each other. They are not tests.

The paper library
  • Library page: every paper, searchable and filterable by year, cohort, cell type and role.
  • Paper page: the full record (authors, journal, DOI, PubMed, abstract), a short summary, topics (cell types, tissues, diseases, methods, cohorts), the datasets it is linked to, related papers, the PDF and a BibTeX entry.
  • Who sees the library. Everyone who can sign in to this site sees every paper and document in it; there are no per-paper restrictions. Text from the library, including passages from papers, may be sent to AI assistants and their providers (see privacy).
  • Roles. Every paper has a role: source (the data in anthive come from this paper), reanalysis (it reanalyses data that are in anthive), method (a method used on anthive data), related (related to a dataset, not its source) or background (of interest to the lab, not linked to any dataset). Background is the default when no role is given.
  • Document types. Besides journal articles and preprints the library can hold books and chapters, conference papers, theses (PhD or master), reports such as project or grant proposals, technical reports and protocols, and manuscripts in preparation. Project proposals are kept in their own folder.
  • Why a paper is linked. Datasets point to papers with a role: source (the data come from this paper), reanalysis, method (a protocol or tool used) or related (for example a preprint of the same study). Related papers are also found automatically, and the page says why: same cohort, another version of the same study, shared authors, same cell type, tissue, disease or method, or one cites the other.
  • Drafts. Summaries and topics marked draft, not yet reviewed were written by a language model from the abstract and methods and still await a curator. Treat them as hints; the PDF and the record are authoritative.
  • Search inside papers. The full text is indexed by section and page; AI assistants can search it and cite the page (see MCP).
  • Adding papers. Admins can add papers; see the library documentation. If you would like a paper added, ask an admin.

Working with AI assistants

You can let an AI assistant (Claude, ChatGPT-based tools, Cursor, VS Code, Codex, OpenCode and others) search, plot and analyse anthive data for you, and read the papers. Two pieces work together:

  • MCP is the live connection: it lets the assistant use anthive, as you, through a personal link.
  • Skills are written know-how installed in your assistant: how to use anthive well, which caveats matter, how to cite. They are loaded automatically when relevant.

Anything anthive returns to your AI client, including text from papers and datasets, is sent to that client's AI provider.

Use both if your assistant supports skills; MCP alone works too.

MCP: connect an assistant

MCP (Model Context Protocol) is a standard way for AI assistants to use outside tools. Anthive runs an MCP server; your assistant connects to it with a personal link that identifies you, so it sees exactly what you may see and acts in your name.

  1. Sign in, open your name at the top right and choose Connect an MCP client (it says MCP links once you have links). This opens your MCP page.
  2. Give the link a name, for example laptop Claude Code, and press Add a link. Make one link per client or computer, so you can replace one without touching the others. Most sites allow up to 5 links per person.
  3. Copy the link, or the ready-made setup snippet for your client (next section).
  4. Rotate a link if you think it leaked: the old address stops working immediately and you paste the new one into your client. Revoke removes a link for good. Links expire after a period set by the site (90 days by default); the page warns when expiry is near and Renew gives a fresh one.
Treat a link like a password. Anyone who has it can query the data as you. Do not paste it into chats, tickets or shared files.

More on links, expiry and what each tool may do: MCP links.

Setting up each client

Almost every AI tool that speaks MCP can use anthive: it is a remote server over HTTP ("streamable HTTP") that needs no sign-in beyond your link. Your MCP page has copy-ready snippets with your own link filled in for the common clients. Step-by-step instructions for each client, kept up to date on GitLab, are in Connecting an AI client to anthive. It covers:

  • Claude: Claude Code, claude.ai, Claude Desktop and mobile
  • OpenAI: Codex (CLI, app, IDE) and ChatGPT developer mode
  • Terminal agents: Gemini CLI, OpenCode, Goose, Amp, Pi, Warp
  • Editors: Cursor, VS Code with GitHub Copilot, Windsurf (Devin Desktop), Zed, Cline, Roo Code, Continue, Kiro, JetBrains AI Assistant and Junie
  • Desktop chat apps: LM Studio, Cherry Studio
  • Anything else that can start a local program, through the mcp-remote bridge

The short version for the most common ones (replace <your link> with your link, https://<this site>/mcp/u/amcp_...):

Claude Code, once in a terminal (add --scope user to use it in every project):

claude mcp add --transport http anthive <your link>

Codex:

codex mcp add anthive --url <your link>

claude.ai and Claude Desktop: Customize, then Connectors, Add custom connector. Name it anthive, paste your link as the URL and choose no sign-in.

Clients with a JSON configuration (Cursor ~/.cursor/mcp.json, Kiro, LM Studio, Junie and others) mostly take:

{ "mcpServers": { "anthive": { "url": "<your link>" } } }

Small differences trip people up: VS Code uses servers instead of mcpServers and needs "type": "http", Gemini CLI wants httpUrl, Windsurf serverUrl, Zed context_servers, Goose uri. The client guide has the exact form for each.

claude.ai, the Claude apps and ChatGPT connect from the vendor's cloud, not from your computer. They only work if this site is reachable from the internet. If it is only reachable on a campus network or VPN, use a client that runs on your machine (Claude Code, Codex, Gemini CLI, Cursor, VS Code, ...) or the mcp-remote bridge.

The name you give the server (anthive above) is how the assistant refers to it, and how its tools and prompts are named in your client. Clients that support custom headers can keep the token out of the URL: see MCP links.

Skills

A skill is a small folder with instructions (a SKILL.md) that your assistant loads by itself when a task fits. Where MCP gives the assistant access, a skill gives it judgement: which tool to call first, how to avoid misleading statistics, how to cite. Skills follow an open format, so the same skills work in Claude Code, Codex, OpenCode, Cursor, Gemini CLI, GitHub Copilot and many other agents.

The anthive skills are public at gitlab.kuleuven.be/bdslab/anthive/skills. Names starting with anthive- need access to an anthive server; names starting with sc- are general single-cell and research practice and work without anthive. Currently:

SkillFor
{{ name }}{{ desc }}

The list grows; the repository always has the current set.

Install in Claude Code, Codex, OpenCode, Cursor, Gemini CLI and other agents. Use the skills command-line tool (needs Node.js). This installs every skill into every agent it finds on your computer:

{{ _skills_install }}

A few agents, such as Eve and PromptScript, report "does not support global skill installation". That is harmless; check the install with ls ~/.agents/skills ~/.claude/skills.

An agent that can run commands can also do this for you: the setup prompt on your MCP page connects anthive and installs the skills in one paste.

Update them now and then:

{{ _skills_update }}

  • To install for certain agents only, name them separated by spaces, for example --agent claude-code codex opencode. Leave out -g to install into the current project only.
  • To install only some skills, add --skill with their names separated by spaces. Adding -l lists what the repository offers without installing anything.

  2. Choose Upload skill (or +) and pick a zip. Repeat for each skill you want, anthive-basics first. anthive-setup helps later, when you update or add a server.

  3. Add your MCP link as a custom connector (Customize > Connectors > Add custom connector, no sign-in) so the skills have something to talk to.

Custom connectors are called from Anthropic's cloud, also from Claude Desktop. They only reach an anthive site that is reachable from the internet. For a site on a campus network or VPN, use Claude Desktop with the mcp-remote bridge, or a client that runs on your machine such as Claude Code or Codex (see the client guide).

The vark skill. If you use vark, vark skill install adds its own skill to the agents on your computer, and vark upgrade keeps it current.

What the skills do not contain. No data, no credentials and no site address: they work with any anthive server. Your assistant still needs a connection, in one of three ways:

  • your personal MCP link from your MCP page (recommended);
  • vark, after vark server login;
  • the REST API, with ANTHIVE_URL=https://<this site> in your environment and your login in ~/.netrc (see the API page).

Assistants without skills support still get the same guidance through MCP: the anthive://guide resource and the prompts.

Several anthive servers

You may have access to more than one anthive server, for example an internal one with everything you may see and a public one. The skills and tools work with any of them.

  • Add one MCP connection per server, each with its own link and a clear name (for example anthive-intern and anthive-public). The assistant should say which server each result came from.
  • Dataset ids such as L26/FMG are unique only within one server; always name the server with the id.
  • Servers hold different data and may run different versions (shown on the version button). Literature search needs version 2.39.0 or newer.
  • Without MCP, assistants and scripts reach a server over plain HTTP: if you use vark, its server list (vark server ls) is used; otherwise set ANTHIVE_URL=https://<site> and put your login in ~/.netrc (machine <site> login <user> password <password>).

Good practice and limits

  • Pseudoreplication. Thousands of cells from a few donors are not independent. Ask for comparisons per donor (ant_donor) and the number of donors before trusting a disease or sex effect.
  • Citations. Ask the assistant to cite literature as [Author Year, p.N] and to keep it separate from what the data show; check important claims in the PDF.
  • Drafts. Paper summaries marked as drafts are model-written; quotes from the paper are more reliable.
  • Permissions. Some tools are admin-only (custom Python figures, reloading the catalogue, adding papers). The assistant gets a clear refusal instead of a result.
  • Privacy. Anything anthive returns to your AI client, including text from papers and datasets, is sent to that client's AI provider (for example Anthropic, OpenAI or the maker of your editor), together with the questions you ask. This applies to every paper and document in the library; none is held back. The underlying expression matrices stay on this server unless a tool returns or you download them. Use a provider and settings you trust for unpublished work.
  • The built-in chat that some sites showed in the corner of the page is switched off; use your own assistant through MCP instead.

Programmatic access

REST API

Everything the site shows comes from a REST API under /api. Start with the API page (the API link in the top bar and in the menu under your name): it explains signing in, keeping your password out of scripts, first calls with curl, pyvark and vark, with this site's address filled in. The interactive documentation is at /api/docs (also /api/redoc). Scripts sign in with your normal username and password over HTTPS; keep them in ~/.netrc and use curl -n:

curl -n -s "https://<this site>/api/databases" | jq '.databases[] | {id, title, n_cells}'
curl -n -s "https://<this site>/api/databases/L26/FMG/plot/violin?x=ant_disease&y=APOE&sample=20000" -o apoe.png

Changes between versions are listed in the changelog.

vark (command line)

vark is a single program for the terminal that queries one or several anthive servers at once.

curl -sSL https://codeberg.org/mfiers/vark/raw/branch/main/install.sh | bash
vark server login --name intern --url https://<this site>/api --user <you>
vark db ls
vark gene-stats L26/FMG APOE
vark plot L26/FMG --geom violin --x ant_disease --y APOE --out apoe.png

vark skill install adds a vark skill to the agents on your computer; vark upgrade refreshes it.

pyvark (Python)

pyvark is the Python client, for scripts and notebooks:

pip install pyvark
python -c "from vark import AnthiveClient; c = AnthiveClient('https://<this site>/api', auth=('<you>', '<password>')); print(len(c.get_databases()))"

Notebooks in the browser

The 📓 notebook button on a plot, and JupyterLite, open notebooks that run in your browser with pyvark preinstalled. Nothing is installed on your computer; download a notebook to keep it.
