Signing in

{% if auth_mode == 'none' %}

This site is a public, read-only mirror. Nobody logs in, so the API needs no username or password. Admin features are switched off.

{% elif auth_mode == 'trusted-proxy' %}

On this site the login is handled by your institute's web server in front of anthive, not by anthive itself. Whether scripts can send a username and password depends on that server; ask the people running this site how to call {{ api_base }} from a script.

{% else %}

The API uses the same username and password as this website. There are no separate API keys. In the browser your login session already covers the API, which is why the interactive docs work right away. Scripts and programs send the username and password with every request using HTTP basic authentication.

  • Always over HTTPS. Basic authentication only encodes the password, it does not encrypt it. HTTPS is what protects it on the way, so always use the https:// address: {{ api_base }}.
  • Only the API takes a password this way. Basic authentication works on addresses under /api/. The web pages themselves always go through the login page.
  • Mistyped passwords lock you out for a while. With the default settings, five failed logins within two minutes block the account for ten minutes, for the website as well. A script with a wrong password in a loop triggers this quickly, so test it with one call first.
  • Who you are matters. The API sees your username, so admin-only endpoints work for admins and refuse everybody else (see below).
{% endif %}

MCP links are separate

The personal links on your MCP page are for AI assistants. Each link is its own token that acts as your login on the MCP server (/mcp); it does not work on the REST API, and your password does not go into an MCP client. Treat a link like a password and revoke it there if it leaks.

Keeping your password out of your code

Never type your password into a script, a notebook, a command line or a file you share or commit. Command lines end up in your shell history and in the process list; notebooks end up on GitHub. Use one of these instead.

A ~/.netrc file (curl, Python)

Open ~/.netrc in a text editor (create it if it does not exist) and add this line with your own password:

machine {{ netrc_host }} login {{ _who }} password YOUR_PASSWORD

Then make it readable for you only:

chmod 600 ~/.netrc

curl -n reads the file. Python's requests (and so pyvark) uses it automatically when you give no other login.

Environment variables

Set them in a session without echoing the password, then read them in your code:

export ANTHIVE_USER={{ _who }}
read -rs -p "anthive password: " ANTHIVE_PASSWORD; export ANTHIVE_PASSWORD; echo

The vark credential store

vark server login keeps the password in your system keyring (or an encrypted file on servers without one), and pyvark can read it from there. See vark.

{% endif %}

First steps with curl

With ~/.netrc in place, -n adds your login to each call. The dataset id L26/FMG is an example; any id from the list works (you can copy ids from the dataset pages).

Is the server up, and which version does it run?

curl -n -s {{ api_base }}/health
curl -n -s {{ api_base }}/version

List the datasets (with jq to keep the output short):

curl -n -s {{ api_base }}/databases | jq '.databases[] | {id, title, n_cells}'

Expression statistics for a few genes in one dataset:

curl -n -s "{{ api_base }}/databases/L26/FMG/gene_stats?genes=APOE,TREM2"

Download a plot as a PNG. The plot endpoints take the same options as the plot builder on the dataset pages; the interactive docs list them for each plot type.

curl -n -s -o apoe_violin.png "{{ api_base }}/databases/L26/FMG/plot/violin?x=ant_disease&y=APOE&sample=20000"

A 401 means the login was missing or wrong (check ~/.netrc and the host name in it). A 403 means you are logged in but the endpoint needs rights you do not have.

Python with pyvark

pyvark is the Python client. The package is called pyvark, but you import it as vark.

pip install pyvark            # or: uv add pyvark
pip install "pyvark[pandas]"  # optional, for format='dataframe'

Pass the API address and read the login from the environment variables above:

import os
from vark import AnthiveClient

client = AnthiveClient(
    "{{ api_base }}",
    auth=(os.environ["ANTHIVE_USER"], os.environ["ANTHIVE_PASSWORD"]),
)
print(client.get_version()["version"])
print(len(client.get_databases()), "datasets")
print(client.get_gene_stats("L26/FMG", ["APOE", "TREM2"]))

With a ~/.netrc entry you can leave out auth= entirely: AnthiveClient("{{ api_base }}").

If you already registered this site with vark, pyvark can reuse that password. Install the extra and again leave out auth=:

pip install "pyvark[vark-config]"

Notebooks opened from this site (the notebook button on a plot, or JupyterLite) run in your browser with pyvark preinstalled and need no setup.

The vark command line

vark is a single program for the terminal (Linux, macOS, Windows). The installer checks the release signature and puts vark on your path:

curl -sSL https://codeberg.org/mfiers/vark/raw/branch/main/install.sh | bash

Register this site once. vark asks for your password, checks that the server answers, and stores the password in your keyring:

vark server login --name anthive --url {{ api_base }} --user {{ _who }}
vark server ls
vark server status

vark can hold several anthive servers at once. Run vark server login again with another --name and --url to add one; listings and searches then cover every reachable server, and --server NAME limits a command to one of them.

vark db ls
vark gene-stats L26/FMG APOE
vark plot L26/FMG --geom violin --x ant_disease --y APOE --out apoe.png

vark and pyvark can also download and upload library papers; see their documentation.

What needs admin rights, and limits

Reading data is open to everyone who can log in: datasets, genes, plots, differential expression, gene sets, read-only SQL and the paper library. A few endpoints change the site or expose other people's data and answer 403 with a short JSON message unless you are an admin:

  • editing collection and dataset descriptions and annotations, and the curation suggestions;
  • server control under /api/admin/ (reloading the catalogue, cache rebuilds);
  • the list of every user's MCP links;
  • custom Python figures (/analytics/viz);
  • adding papers to the library, which is limited to the upload groups the site configures (admins by default).

The API has no request rate limit of its own, but please do not hammer it: plots are cached, and one call per figure is plenty. These limits do apply:

WhatLimit
SQL on one dataset (/databases/{id}/query/sql)SELECT only, at most 100,000 rows
Analytics queries (/databases/{id}/analytics/query)SELECT only, at most 500,000 rows, stopped after 120 s by default
Custom Python figures (admins)stopped after 60 s by default
Paper PDF upload25 MB by default
Failed logins5 within 2 minutes block the account for 10 minutes (default)
