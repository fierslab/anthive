# Server Configuration Files

Post-2026-06 refactor: Caddy is the **single source of truth** for path
routing on both dev and prod.  Nginx (when present on prod) is a thin
SSL + Authelia shim that forwards EVERY anthive path to Caddy on a
loopback port.

## Files — Caddy

- **`Caddyfile`** — main Caddy config. Reads four env vars at startup
  (`ANTHIVE_LISTEN`, `ANTHIVE_TLS_SNIPPET`, `ANTHIVE_AUTH_SNIPPET`,
  `ANTHIVE_HTTP_REDIRECT_SNIPPET`) to flip between dev and prod modes.
  All path routing (`/api/*`, `/browse/*`, `/jupyter/*`, `/mcp*`,
  `/artifacts/*`, `/authelia/*`, `/.well-known/*`, `/streamlit*`,
  fallback to ant-browse) lives here, identical on dev and prod.

- **`caddy-tls.dev`** — TLS snippet for dev: `tls internal` (Caddy's
  local self-signed CA).
- **`caddy-tls.prod`** — empty (nginx terminates TLS on prod).

- **`caddy-auth.dev`** — Authelia forward_auth snippet for dev (cookie
  vs basic-auth split on `/api/*` vs everything else).
- **`caddy-auth.prod`** — empty (nginx authenticates upstream and
  forwards Remote-User/Groups/Email headers — Caddy trusts them).

- **`caddy-http-redirect.dev`** — :8500 → :8501 HTTPS redirect block
  for dev convenience.
- **`caddy-http-redirect.prod`** — empty (prod Caddy IS the :8500
  listener — a redirect block would collide).

- **`Caddyfile-prod-snippet`** — annotated reference of the env-var
  values that select prod mode. Not loaded by Caddy.

- **`caddy-auth.example`** — template for the gitignored
  `caddy-auth-basic.conf` (HTTP basic auth). Generated by
  `make caddy-passwd`.

## Files — nginx

- **`nginx.conf`** — standalone dev/test variant of the thin shim:
  listens on :8501, forwards EVERYTHING to Caddy on 127.0.0.1:8500.
  Usage: `make serve-nginx` (requires `make serve-prod` running in
  another terminal).

- **`nginx-intern-anthive.conf`** — the **production** vhost: SSL
  termination + Authelia `auth_request` gate + single `location /`
  forwarding to Caddy. Drop into `/etc/nginx/sites-available/` on
  prod; see `doc/DEPLOY.md` for the full recipe.

- **`default.conf`** — legacy data.nevel.eu vhost (pre-refactor,
  has per-path routing). Kept for reference; prefer the new
  thin-shim pattern.

- **`nginx-data.nevel.eu.authelia.conf`** — Authelia-augmented
  legacy vhost. Same caveat as above.

## Files — Authelia

- **`authelia/`** — Authelia v4.39 config + secrets dir (gitignored
  secrets/). See `doc/HANDOFF_authelia.md`.

## How to launch

**Dev (Caddy on :8501 with TLS internal — historical behaviour):**

```bash
make serve-debug                            # supervisor + Caddy in dev mode
```

**Prod (Caddy on 127.0.0.1:8500, nginx in front):**

```bash
make serve-prod                             # supervisor + Caddy in prod mode
# In another terminal (or via /etc/nginx/sites-enabled/):
sudo nginx -t && sudo systemctl reload nginx
```

See `doc/DEPLOY.md` for the prod recipe in detail.
